## Resolved findings

The initial audit's NUL lookup, cancellation and provider probes returned sanitized 500 because PostgreSQL rejected decoded NUL text (22021). New tests reproduced all three failures before shared pre-SQL validation changed them to owner-approved 400. Valid arbitrary strings and 401 precedence still pass. No SQL exception details or keys leak in those tested responses.

Hardening added safe primary idle-pool handling and tested an actual session disconnect. A test-only Supertest header typing correction retained repeated-header coverage. No schema/index recreation or public endpoint change was made.

## Dependency security review

Fresh full audits on 9 November reported backend **32 package findings (27 moderate, 5 low)** and frontend **8 moderate**; zero high/critical. Both production-only audits returned zero findings. Full audits still exit 1; this is not a clean full-tree or exploitability guarantee.

## Outstanding acceptance and coverage

- Obtain authorization and verify hosted HTTPS, Neon TLS/writer capacity, migrations/index installation, persistence and secret configuration.
- Review backups/restore, cold starts, load/failover, logging/redaction and retained patient data. Do not reset production as a smoke test.
- ID/email lookup is the assessment model, not patient authentication. Direct reset uses the same integration key; keep it private.
- Formal accessibility, screen-reader/cross-browser certification, full secret-history scanning and production-log audits were not executed.
- A dedicated repeated-cancellation-click UI case and a real >10-row browser Load more case are not covered; related API/controlled UI tests do not prove them.
